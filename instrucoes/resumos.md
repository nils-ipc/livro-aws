# Formato dos resumos de capítulo

Um arquivo por capítulo: `notas/resumos/NN-nome-do-capitulo.md`. Escrito por quem escreveu o capítulo, ao final. Serve de memória para os capítulos seguintes, que leem os resumos em vez dos capítulos inteiros.

Estilo telegráfico (caveman): sem artigos, fragmentos, uma informação por linha. Manter exatos nomes, números, comandos, nomes de arquivos e recursos. Máximo de ~300 palavras. Estas notas nunca vão para o livro, e o livro nunca usa este estilo.

```markdown
# Resumo NN — Título

## Conceitos explicados (não reexplicar depois)
- conceito: como foi explicado em 1 linha, analogia usada

## Estado do Rangô ao fim
- arquitetura, serviços, arquivos, recursos AWS criados (nomes), o que foi destruído

## Casos reais e exemplos usados (não repetir)
- ...

## Promessas feitas
- ponte: problema anunciado para o próximo capítulo (frase da ponte quase literal)
- outras promessas ("veremos no capítulo X")
```
